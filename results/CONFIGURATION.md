# Configuration of every experiment

Generated by `uv run python -m bench.config_report` from `docker-compose.yml`, `infra/kafka/create-topics.sh`, `generator/tradegen/cli.py` and `bench/experiments/*.yaml`; do not edit by hand (a test fails when this file is out of date). Every run also stores its own parameters, git commit and machine in `config.json` under `results/raw/` (git-ignored; the summaries are in `summary.csv`). Machine and versions: [MACHINE.md](MACHINE.md).

## 2. Per experiment

### E1a: producer batching (reproduction a)

Kafka's own `kafka-producer-perf-test.sh` runs inside `kafka-1` against topic `perf_test` (1 partition, RF 1, min ISR 1; the other topics are not involved). 10,000,000 records of 200 bytes, `--throughput -1`, `acks=0`, no Spark. Topic recreated before each setting; the producer and the broker share the machine.

| Setting | batch.size (bytes) | linger.ms |
|---|---|---|
| `batch-1` | 0 | 0 |
| `batch-10` | 2000 | 10 |
| `batch-50` | 10,000 | 10 |
| `batch-100` | 20,000 | 10 |
| `batch-200` | 40,000 | 10 |

### E1b: continuous versus micro-batch (reproduction b)

Pass-through job (`spark-passthrough`, `trades` to `passthrough_out`, no state), generator in `realtime` mode with `acks=all` and idempotence on. `trades` and `passthrough_out` have as many partitions as the setting says (RF 3, min ISR 2). Continuous mode: `trigger(continuous='1 second')` (the checkpoint interval); micro-batch: `processingTime` trigger. `startingOffsets=latest`.

| Setting | mode | partitions | trigger | input rates (records/s) |
|---|---|---|---|---|
| `continuous-p4` | continuous | 4 | n/a (continuous) | 5000, 10,000, 20,000, 40,000, 80,000 |
| `microbatch-p4-100ms` | microbatch | 4 | 100 milliseconds | 40,000, 80,000, 100,000 |

Run length per rate: 300 s (continuous curve points use 120 s), warm-up discarded 30 s (20 s for continuous), three repeats; micro-batch searches for the highest rate that keeps up (decision D5).

### E1c: partitions and trigger interval (RQ1)

The real bars job (`spark-bars`, `local[4]`, watermark `10 seconds`, `SINK_MODE=upsert`, `spark.sql.shuffle.partitions=4`), micro-batch with a `processingTime` trigger. Generator in `realtime` mode, `acks=all`, idempotence on, `--no-flush-trade`. `trades` has the partition count of the setting (RF 3, min ISR 2), `startingOffsets=latest`, PostgreSQL truncated and Kafka topic recreated before each step.

| Setting | partitions | trigger | input rates (records/s) |
|---|---|---|---|
| `p6-1s` | 6 | 1 second | 30,000, 60,000, 90,000 |
| `p1-1s` | 1 | 1 second | 30,000, 60,000, 90,000 |
| `p3-1s` | 3 | 1 second | 30,000, 60,000, 90,000 |
| `p6-100ms` | 6 | 100 milliseconds | 30,000, 60,000, 90,000 |
| `p6-500ms` | 6 | 500 milliseconds | 30,000, 60,000, 90,000 |

Each step: 300 s, first 70 s discarded from latency, three repeats.

### E2: broker crash (RQ2)

Bars job (defaults above), `trades` with 6 partitions (RF 3, min ISR 2, unclean election off), `startingOffsets=earliest`. Generator in `virtual` mode: seed 42, 40 virtual minutes at speed 10x, 1.0 trades per symbol per virtual second, per-trade acknowledgement log. At 50 % of the run the harness runs `docker kill` on the broker leading partition 0 and restarts it afterwards.

| Setting | acks | idempotence | kills (repeats) |
|---|---|---|---|
| `acks-all` | all | true | 3 |
| `acks-1` | 1 | false | 6 |
| `acks-all-no-idempotence` | all | false | 3 |

With `acks=1` the producer cannot enable idempotence (Kafka rejects the combination), so a producer retry can duplicate a trade.

### E3: Spark crash (RQ2)

Bars job (defaults above), `trades` with 6 partitions, generator `acks=all`, idempotence on. The Spark container is sent `SIGKILL` at 50 % of the stream (live) or after batch 5 (deterministic) and restarted at once on the same checkpoint volume.

| Setting | Input | Spark settings |
|---|---|---|
| `live` | virtual mode, seed 42, 40 min at 10x, paced | defaults |
| `deterministic` | golden dataset preloaded (`data/sample`, 60,163 trades), replay at maximum speed | `MAX_OFFSETS_PER_TRIGGER=5000`, `STARTING_OFFSETS=earliest` |

### E4: cost of exactly-once output (RQ3)

Bars job (defaults above); `SINK_MODE` selects the table and write statement (`insert`: plain `INSERT` into `bars_plain`/`alerts_plain`; `upsert`: `INSERT ... ON CONFLICT DO UPDATE` into `bars`/`alerts`). `crash` runs replay the golden dataset with `MAX_OFFSETS_PER_TRIGGER=5000` and `FAULT_AFTER_BATCH=5` (Spark kills its own JVM after the database commit and before recording the batch). `cost` runs are crash-free, realtime at 2000 records/s for 300 s, warm-up 70 s.

| Setting | kind | sink |
|---|---|---|
| `insert-crash` | crash | insert |
| `upsert-crash` | crash | upsert |
| `insert-cost` | cost | insert |
| `upsert-cost` | cost | upsert |

## 3. Where each value lives

Experiment parameters: `bench/experiments/*.yaml`; stack: `docker-compose.yml`; topics: `infra/kafka/create-topics.sh`; producer: `generator/tradegen/cli.py`; Spark options: `spark/bars_job.py`, `spark/passthrough_job.py`. Environment variables such as `TRIGGER_INTERVAL`, `SINK_MODE` and `MAX_OFFSETS_PER_TRIGGER` are set per step by `bench/runner.py`.
